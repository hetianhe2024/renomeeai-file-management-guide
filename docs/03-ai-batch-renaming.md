# AI 批量重命名如何工作

AI batch file renaming 不是让模型直接改磁盘上的文件。可靠的实现是一条固定流水线：判断每个文件能提供哪些字段，按你的指令选出字段，生成候选文件名，检查冲突，预览，然后才重命名。模型只出现在“读懂指令”和“把杂乱文本收成短名”这两处。拍摄时间、PDF 信息字典、ID3 标签都是确定性读取，不必调用模型。

## 三条信息，三种成本

| 层级 | 读取什么 | 失败时的表现 | 通常是否需要模型 |
| --- | --- | --- | --- |
| 文件名 | 已有字符串 | 名字本身没有信息时无效 | 否。正则或替换即可 |
| 文件系统 | 修改时间、大小、扩展名 | 复制后时间已变 | 否 |
| 文件内容 | PDF 文本、EXIF、ID3、OCR 结果 | 字段为空，或识别错字 | 字段整齐时否；要从长文本里归纳标题时是 |

先用便宜的一层。一批 `2024_报告_A.pdf` 要改成 `2025_报告_A.pdf`，替换前缀即可。一批 `IMG_*.jpg` 要按拍摄时间排序，读取 EXIF，不要把图片交给视觉模型。只有当目标名来自正文、票据上的供应商，或一张没有文字层的扫描件时，才进入内容识别。

## 流水线

一次批量任务按下面的顺序做。顺序颠倒时，最常见的事故是还没预览就把文件改掉了。

1. **识别类型。** 用扩展名和文件头区分 PDF、JPEG、HEIC、MP3。扩展名可以撒谎，文件头更可靠。
2. **抽取候选字段。** PDF 读信息字典和首页文本；照片读 `DateTimeOriginal`、`Model`、GPS；音频读 ID3。扫描件先做 OCR，得到的是文本，还不是文件名。
3. **按指令选择字段。** “用作者和年份”与“用发票日期和供应商”选出的字段不同。指令清楚时，这一步是映射；指令含糊时，模型会猜。
4. **规范化。** 去掉 `\ / : * ? " < > |`，压缩连续空格，截断过长标题，保留原扩展名。Windows 还要去掉结尾的空格和句点。
5. **冲突检查。** 两个文件算出同一个名字时，追加 `_02`，或停下来让人决定。静默覆盖是错误行为。
6. **预览。** 列出每一个旧名和新名。人在这一步否决错误的标题。
7. **执行与撤销。** 只改名称，不改字节内容。保留本次映射，才能改回去。

模型的输出要经过第 4 步和第 5 步。不要把模型返回的字符串原样当作文件名。

## 模型适合做什么，不适合做什么

适合：

- 把自然语言指令对应到已抽出的字段。例如“按拍摄日期加序号”。
- 从首页文本里挑出标题行、作者、发票号，并压成适合文件名的长度。
- 在 OCR 文本有错字时，结合上下文给出一个仍可核对的候选。

不适合单独信任：

- 文档里没有的标题。预览里对不上原文的名字应改回原文片段。
- 法律、金额、文号。这些字符必须能在源文本里找到，不能靠“通常是这样”补全。
- 空文件、加密 PDF、只有图片的扫描件。没有可读文本时，模型会用文件名或空泛词凑一个名字。

因此预览不是界面上的附加按钮，而是这条流水线的校验点。官方 FAQ 写明：重名会在预览阶段提示，并可以用编号避开冲突，或跳过这些文件[^renomeeFaq]。

[^renomeeFaq]: <https://renomeeai.readthedocs.io/en/latest/en/faq/>

## 一个对照

同一目录里有三种文件。正确的做法是分路，而不是对全部文件使用同一种“AI 命名”。

```text
report_final_v3.pdf     信息字典标题为 "Image Recognition Survey"
IMG_4829.jpg             DateTimeOriginal = 2024:03:15 14:30:22
scan001.pdf              无文本层，首页是一张发票照片
```

处理后：

```text
2024_zhang_image-recognition-survey.pdf
2024-03-15_143022.jpg
2026-04-15_acme_1280.pdf
```

第一个名字来自 PDF 字段，第二个来自 EXIF，第三个来自 OCR 后的供应商、日期和金额。三个结果都应该能在源文件里指出依据。指不出依据的候选名，在预览里删掉。

只想替换文件名中的一段时，不必读取内容。下面的命令只打印、不改名[^renameItem]：

[^renameItem]: <https://learn.microsoft.com/powershell/module/microsoft.powershell.management/rename-item>

```powershell
Get-ChildItem -Filter "2024_*.pdf" |
  Rename-Item -NewName { $_.Name -replace '^2024_', '2025_' } -WhatIf
```

确认输出后再去掉 `-WhatIf`。这种改法没有内置撤销，执行前把原文件名列表存下来。

## 数据离开本机的范围

内容识别会碰到隐私问题。下面按 RenomeeAI 官方 FAQ 转述[^renomeeFaq]，核对日期 2026-11-12。官网功能页的个别句子与 FAQ 不一致；本文以 FAQ 为准，并以应用里当时弹出的确认提示为准。

- 前缀、序号、按拍摄日期读取 EXIF：不上传文件内容。FAQ 同时写明这些基础操作可以离线完成。
- 基于内容的 PDF、图片和扫描件：在应用内明确允许之后，发送文档的前 3 页，或发送图像文件。
- Word 与 Excel：在本机读取前 3 页，只把提取出的文本发到服务器，不上传原始文件。
- 传输使用 TLS 1.3。FAQ 写明这些数据只用于当次命名，处理完成后删除，服务器不保留文件副本。

需要模型阅读正文、做 OCR 或描述图像时，必须能访问 RenomeeAI 的服务。只读 EXIF 拍摄日期则不依赖网络。

功能页列出的读取范围可以用来选择路径：带文本的 PDF 在 50MB 以内读取标题、作者和正文；图片的 EXIF 与 OCR 分开，EXIF 不走 OCR。完整字段表见功能说明[^renomeeFeatures]。速度数字各页面并不一致，本文不引用具体秒数。定性关系是稳定的：只改文件名最快，读元数据次之，OCR 因为要识别图像中的文字，比直接读文本层更慢。

[^renomeeFeatures]: <https://renomeeai.com/en/product/features/>
